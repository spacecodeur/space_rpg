1//! # Nested StatefulWidget Pattern
2//!
3//! This example demonstrates composing multiple `StatefulWidget`s in a parent-child hierarchy.
4//! This pattern is ideal for complex applications where you need clean separation of concerns
5//! and want to leverage the benefits of the StatefulWidget pattern at multiple levels.
6//!
7//! This example runs with the Ratatui library code in the branch that you are currently
8//! reading. See the [`latest`] branch for the code which works with the most recent Ratatui
9//! release.
10//!
11//! [`latest`]: https://github.com/ratatui/ratatui/tree/latest
12//!
13//! ## When to Use This Pattern
14//!
15//! - Complex applications with hierarchical state management needs
16//! - When you want clean separation between widgets and their state
17//! - Building composable widget systems
18//! - Applications that need testable, reusable widget components
19//!
20//! ## Trade-offs
21//!
22//! **Pros:**
23//! - Excellent separation of concerns
24//! - Highly composable and reusable widgets
25//! - Easy to test individual widgets and their state
26//! - Scales well with application complexity
27//! - Follows idiomatic Ratatui patterns
28//!
29//! **Cons:**
30//! - More boilerplate code than simpler patterns
31//! - Requires understanding of nested state management
32//! - State structures can become complex
33//! - May be overkill for simple applications
34//!
35//! ## Example Usage
36//!
37//! The parent `App` widget manages application-level state while delegating specific
38//! functionality to child widgets like `Counter`. Each widget is responsible for its own
39//! state type and rendering logic, making the system highly modular.
40
41use ratatui::DefaultTerminal;
42use ratatui::buffer::Buffer;
43use ratatui::layout::Rect;
44use ratatui::widgets::{StatefulWidget, Widget};
45use ratatui_state_examples::is_exit_key_pressed;
46
47/// Demonstrates the nested StatefulWidget pattern for mutable state management.
48///
49/// Creates a parent-child widget hierarchy using StatefulWidgets and runs the application loop,
50/// updating the counter on each render cycle until the user exits.
51fn main() -> color_eyre::Result<()> {
52    color_eyre::install()?;
53    ratatui::run(App::run)
54}
55
56/// The main application widget using the StatefulWidget pattern.
57///
58/// Demonstrates how to compose multiple StatefulWidgets together while coordinating
59/// between different child widgets.
60struct App;
61
62impl App {
63    /// Run the application with the given terminal.
64    fn run(terminal: &mut DefaultTerminal) -> color_eyre::Result<()> {
65        let mut state = AppState { counter: 0 };
66
67        loop {
68            terminal.draw(|frame| frame.render_stateful_widget(App, frame.area(), &mut state))?;
69            if is_exit_key_pressed()? {
70                break Ok(());
71            }
72        }
73    }
74}
75
76/// Application state that contains all the state needed by the app and its child widgets.
77///
78/// Demonstrates how to organize hierarchical state in the StatefulWidget pattern.
79struct AppState {
80    counter: usize,
81}
82
83impl StatefulWidget for App {
84    type State = AppState;
85
86    fn render(self, area: Rect, buf: &mut Buffer, state: &mut Self::State) {
87        Counter.render(area, buf, &mut state.counter);
88    }
89}
90
91/// A counter widget that uses StatefulWidget for clean state separation.
92///
93/// Focuses purely on rendering logic and can be reused with different state instances.
94struct Counter;
95
96impl StatefulWidget for Counter {
97    type State = usize;
98
99    fn render(self, area: Rect, buf: &mut Buffer, state: &mut Self::State) {
100        *state += 1;
101        format!("Counter: {state}").render(area, buf);
102    }
103}
