1//! # Lifetime-Based Mutable References Pattern
2//!
3//! This example demonstrates storing mutable references directly in widget structs using explicit
4//! lifetimes. This is an advanced pattern that provides zero-cost state access but requires
5//! careful lifetime management.
6//!
7//! This example runs with the Ratatui library code in the branch that you are currently
8//! reading. See the [`latest`] branch for the code which works with the most recent Ratatui
9//! release.
10//!
11//! [`latest`]: https://github.com/ratatui/ratatui/tree/latest
12//!
13//! ## When to Use This Pattern
14//!
15//! - You need maximum performance with zero runtime overhead
16//! - You have a good understanding of Rust lifetimes and borrowing
17//! - State lifetime is clearly defined and relatively simple
18//! - You're building performance-critical applications
19//!
20//! ## Trade-offs
21//!
22//! **Pros:**
23//! - Zero runtime cost - no reference counting or runtime borrow checking
24//! - Compile-time safety - borrow checker ensures memory safety
25//! - Direct access to state without indirection
26//! - Maximum performance for state access
27//!
28//! **Cons:**
29//! - Complex lifetime management - requires deep Rust knowledge
30//! - Easy to create compilation errors that are hard to understand
31//! - Inflexible - lifetime constraints can make code harder to refactor
32//! - Not suitable for beginners - requires advanced Rust skills
33//! - Widget structs become less reusable due to lifetime constraints
34//!
35//! ## Important Considerations
36//!
37//! - The widget's lifetime is tied to the state's lifetime
38//! - You must ensure the state outlives the widget
39//! - Lifetime annotations can become complex in larger applications
40//! - Consider simpler patterns unless performance is critical
41//!
42//! ## Example Usage
43//!
44//! The widget stores a mutable reference to external state, allowing direct access without
45//! runtime overhead. The widget must be recreated for each render call due to the lifetime
46//! constraints.
47
48use ratatui::buffer::Buffer;
49use ratatui::layout::Rect;
50use ratatui::widgets::Widget;
51use ratatui_state_examples::is_exit_key_pressed;
52
53/// Demonstrates the lifetime-based mutable references pattern for mutable state management.
54///
55/// Creates a counter widget using mutable references with explicit lifetimes and runs the
56/// application loop, updating the counter on each render cycle until the user exits.
57fn main() -> color_eyre::Result<()> {
58    color_eyre::install()?;
59    ratatui::run(|terminal| {
60        let mut count = 0;
61        loop {
62            let counter = CounterWidget { count: &mut count };
63            terminal.draw(|frame| frame.render_widget(counter, frame.area()))?;
64            if is_exit_key_pressed()? {
65                break Ok(());
66            }
67        }
68    })
69}
70
71/// A counter widget that holds a mutable reference to external state.
72///
73/// Demonstrates the lifetime-based pattern where the widget directly stores a
74/// mutable reference to external state.
75struct CounterWidget<'a> {
76    count: &'a mut usize,
77}
78
79impl Widget for CounterWidget<'_> {
80    fn render(self, area: Rect, buf: &mut Buffer) {
81        *self.count += 1;
82        format!("Counter: {count}", count = self.count).render(area, buf);
83    }
84}
