23//!
24//! [Ratatui][Ratatui Website] is a crate for cooking up terminal user interfaces in Rust. It is a
25//! lightweight library that provides a set of [widgets](`widgets`) and utilities to build complex
26//! Rust TUIs. Ratatui was forked from the [tui-rs] crate in 2023 in order to continue its
27//! development.
28//!
29//! ## Quickstart
30//!
31//! Add `ratatui` and `crossterm` as dependencies to your cargo.toml:
32//!
33//! ```shell
34//! cargo add ratatui crossterm
35//! ```
36//!
37//! Then you can create a simple "Hello World" application:
38//!
39//! ```rust,no_run
40//! use crossterm::event;
41//!
42//! fn main() -> std::io::Result<()> {
43//!     ratatui::run(|mut terminal| {
44//!         loop {
45//!             terminal.draw(|frame| frame.render_widget("Hello World!", frame.area()))?;
46//!             if event::read()?.is_key_press() {
47//!                 break Ok(());
48//!             }
49//!         }
50//!     })
51//! }
52//! ```
53//!
54//! The full code for this example which contains a little more detail is in the [Examples]
55//! directory. For more guidance on different ways to structure your application see the
56//! [Application Patterns] and [Hello Ratatui tutorial] sections in the [Ratatui Website] and the
57//! various [Examples]. There are also several starter [Templates] available to help you get
58//! started quickly with common patterns.

84//! # Crate Organization
85//!
86//! Starting with Ratatui 0.30.0, the project was reorganized into a modular workspace to improve
87//! compilation times, API stability, and dependency management. Most applications should continue
88//! using this main `ratatui` crate, which re-exports everything for convenience:
89//!
90//! - **[`ratatui`](crate)**: Main crate with complete functionality (recommended for apps)
91//! - **[`ratatui-core`]**: Core traits and types for widget libraries
92//! - **[`ratatui-widgets`]**: Built-in widget implementations
93//! - **Backend crates**: [`ratatui-crossterm`], [`ratatui-termion`], [`ratatui-termwiz`]
94//! - **[`ratatui-macros`]**: Macros for simplifying the boilerplate
95//!
96//! **For application developers**: No changes needed - continue using `ratatui` as before.
97//!
98//! **For widget library authors**: Consider depending on [`ratatui-core`] instead of the full
99//! `ratatui` crate for better API stability and reduced dependencies.
100//!
101//! See [ARCHITECTURE.md] for detailed information about the crate organization and design
102//! decisions.
103//!
104//! # Writing Applications
105//!
106//! Ratatui is based on the principle of immediate rendering with intermediate buffers. This means
107//! that for each frame, your app must render all [`widgets`] that are supposed to be part of the
108//! UI. This is in contrast to the retained mode style of rendering where widgets are updated and
109//! then automatically redrawn on the next frame. See the [Rendering] section of the [Ratatui
110//! Website] for more info.
111//!
112//! Ratatui uses [Crossterm] by default as it works on most platforms. See the [Installation]
113//! section of the [Ratatui Website] for more details on how to use other backends ([Termion] /
114//! [Termwiz]).
115//!
116//! Every application built with `ratatui` needs to implement the following steps:
117//!
118//! - Initialize the terminal (see the [`init` module] for convenient initialization functions)
119//! - A main loop that:
120//!   - Draws the UI
121//!   - Handles input events
122//! - Restore the terminal state
123//!
124//! ## Initialize and restore the terminal
125//!
126//! The simplest way to initialize and run a terminal application is to use the [`run()`] function,
127//! which handles terminal initialization, restoration, and panic hooks automatically:
128//!
129//! ```rust,no_run
130//! fn main() -> std::io::Result<()> {
131//!     ratatui::run(|mut terminal| {
132//!         loop {
133//!             terminal.draw(render)?;
134//!             if should_quit()? {
135//!                 break Ok(());
136//!             }
137//!         }
138//!     })
139//! }
140//!
141//! fn render(frame: &mut ratatui::Frame) {
142//!     // ...
143//! }
144//!
145//! fn should_quit() -> std::io::Result<bool> {
146//!     // ...
147//! #   Ok(false)
148//! }
149//! ```
150//!
151//! For more control over initialization and restoration, you can use [`init()`] and [`restore()`]:
152//!
153//! ```rust,no_run
154//! fn main() -> std::io::Result<()> {
155//!     let mut terminal = ratatui::init();
156//!     let result = run_app(&mut terminal);
157//!     ratatui::restore();
158//!     result
159//! }
160//!
161//! fn run_app(terminal: &mut ratatui::DefaultTerminal) -> std::io::Result<()> {
162//!     loop {
163//!         terminal.draw(render)?;
164//!         if should_quit()? {
165//!             break Ok(());
166//!         }
167//!     }
168//! }
169//! # fn render(_frame: &mut ratatui::Frame) {}
170//! # fn should_quit() -> std::io::Result<bool> { Ok(false) }
171//! ```
172//!
173//! Note that when using [`init()`] and [`restore()`], it's important to use a separate function
174//! for the main loop to ensure that [`restore()`] is always called, even if the `?` operator
175//! causes early return from an error.
176//!
177//! For more detailed information about initialization options and when to use each function, see
178//! the [`init` module] documentation.
179//!
180//! ### Manual Terminal and Backend Construction
181//!
182//! Before the convenience functions were introduced in version 0.28.1 ([`init()`]/[`restore()`])
183//! and 0.30.0 ([`run()`]), applications constructed [`Terminal`] and [`Backend`] instances
184//! manually. This approach is still supported for applications that need fine-grained control over
185//! initialization. See the [`Terminal`] and [`backend`] module documentation for details.
186//!
187//! See the [`backend` module] and the [Backends] section of the [Ratatui Website] for more info on
188//! the alternate screen and raw mode. Learn more about different backend options in the [Backend
189//! Comparison] guide.
190//!
191//! ## Drawing the UI
192//!
193//! Drawing the UI is done by calling the [`Terminal::draw`] method on the terminal instance. This
194//! method takes a closure that is called with a [`Frame`] instance. The [`Frame`] provides the size
195//! of the area to draw to and allows the app to render any [`Widget`] using the provided
196//! [`render_widget`] method. After this closure returns, a diff is performed and only the changes
197//! are drawn to the terminal. See the [Widgets] section of the [Ratatui Website] and the [Widget
198//! Recipes] for more info on creating effective UIs.
199//!
200//! The closure passed to the [`Terminal::draw`] method should handle the rendering of a full frame.
201//! For guidance on setting up the terminal before drawing, see the [`init` module] documentation.
202//!
203//! ```rust,no_run
204//! use ratatui::Frame;
205//! use ratatui::widgets::Paragraph;
206//!
207//! fn run(terminal: &mut ratatui::DefaultTerminal) -> std::io::Result<()> {
208//!     loop {
209//!         terminal.draw(|frame| render(frame))?;
210//!         if handle_events()? {
211//!             break Ok(());
212//!         }
213//!     }
214//! }
215//!
216//! fn render(frame: &mut Frame) {
217//!     let text = Paragraph::new("Hello World!");
218//!     frame.render_widget(text, frame.area());
219//! }
220//! # fn handle_events() -> std::io::Result<bool> { Ok(false) }
221//! ```
222//!
223//! ## Handling events
224//!
225//! Ratatui does not include any input handling. Instead event handling can be implemented by
226//! calling backend library methods directly. See the [Handling Events] section of the [Ratatui
227//! Website] for conceptual information. For example, if you are using [Crossterm], you can use the
228//! [`crossterm::event`] module to handle events.
229//!
230//! ```rust,no_run
231//! use crossterm::event::{self, Event, KeyCode, KeyEvent, KeyEventKind};
232//!
233//! fn handle_events() -> std::io::Result<bool> {
234//!     match event::read()? {
235//!         Event::Key(key) if key.kind == KeyEventKind::Press => match key.code {
236//!             KeyCode::Char('q') => return Ok(true),
237//!             // handle other key events
238//!             _ => {}
239//!         },
240//!         // handle other events
241//!         _ => {}
242//!     }
243//!     Ok(false)
244//! }
245//! ```
246//!
247//! ## Layout
248//!
249//! The library comes with a basic yet useful layout management object called [`Layout`] which
250//! allows you to split the available space into multiple areas and then render widgets in each
251//! area. This lets you describe a responsive terminal UI by nesting layouts. See the [Layout]
252//! section of the [Ratatui Website] for more info, and check out the [Layout Recipes] for
253//! practical examples.
254//!
255//! ```rust,no_run
256//! use ratatui::Frame;
257//! use ratatui::layout::{Constraint, Layout};
258//! use ratatui::widgets::Block;
259//!
260//! fn draw(frame: &mut Frame) {
261//!     use Constraint::{Fill, Length, Min};
262//!
263//!     let vertical = Layout::vertical([Length(1), Min(0), Length(1)]);
264//!     let [title_area, main_area, status_area] = vertical.areas(frame.area());
265//!     let horizontal = Layout::horizontal([Fill(1); 2]);
266//!     let [left_area, right_area] = horizontal.areas(main_area);
267//!
268//!     frame.render_widget(Block::bordered().title("Title Bar"), title_area);
269//!     frame.render_widget(Block::bordered().title("Status Bar"), status_area);
270//!     frame.render_widget(Block::bordered().title("Left"), left_area);
271//!     frame.render_widget(Block::bordered().title("Right"), right_area);
272//! }
273//! ```
274//!
275//! Running this example produces the following output:
276//!
277//! ```text
278//! Title Bar───────────────────────────────────
279//! ┌Left────────────────┐┌Right───────────────┐
280//! │                    ││                    │
281//! └────────────────────┘└────────────────────┘
282//! Status Bar──────────────────────────────────
283//! ```
284//!
285//! ## Text and styling
286//!
287//! The [`Text`], [`Line`] and [`Span`] types are the building blocks of the library and are used in
288//! many places. [`Text`] is a list of [`Line`]s and a [`Line`] is a list of [`Span`]s. A [`Span`]
289//! is a string with a specific style.
290//!
291//! The [`style` module] provides types that represent the various styling options. The most
292//! important one is [`Style`] which represents the foreground and background colors and the text
293//! attributes of a [`Span`]. The [`style` module] also provides a [`Stylize`] trait that allows
294//! short-hand syntax to apply a style to widgets and text. See the [Styling Text] section of the
295//! [Ratatui Website] for more info, and explore the [Styling Recipes] for creative examples.
296//!
297//! ```rust,no_run
298//! use ratatui::Frame;
299//! use ratatui::layout::{Constraint, Layout};
300//! use ratatui::style::{Color, Modifier, Style, Stylize};
301//! use ratatui::text::{Line, Span};
302//! use ratatui::widgets::{Block, Paragraph};
303//!
304//! fn draw(frame: &mut Frame) {
305//!     let areas = Layout::vertical([Constraint::Length(1); 4]).split(frame.area());
306//!
307//!     let line = Line::from(vec![
308//!         Span::raw("Hello "),
309//!         Span::styled(
310//!             "World",
311//!             Style::new()
312//!                 .fg(Color::Green)
313//!                 .bg(Color::White)
314//!                 .add_modifier(Modifier::BOLD),
315//!         ),
316//!         "!".red().on_light_yellow().italic(),
317//!     ]);
318//!     frame.render_widget(line, areas[0]);
319//!
320//!     // using the short-hand syntax and implicit conversions
321//!     let paragraph = Paragraph::new("Hello World!".red().on_white().bold());
322//!     frame.render_widget(paragraph, areas[1]);
323//!
324//!     // style the whole widget instead of just the text
325//!     let paragraph = Paragraph::new("Hello World!").style(Style::new().red().on_white());
326//!     frame.render_widget(paragraph, areas[2]);
327//!
328//!     // use the simpler short-hand syntax
329//!     let paragraph = Paragraph::new("Hello World!").blue().on_yellow();
330//!     frame.render_widget(paragraph, areas[3]);
331//! }
332//! ```
