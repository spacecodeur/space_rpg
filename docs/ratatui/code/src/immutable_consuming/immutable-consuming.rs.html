1//! # Consuming Widget Pattern with Immutable State
2//!
3//! This example demonstrates implementing the `Widget` trait directly on the widget type,
4//! causing it to be consumed when rendered. This was the original pattern in Ratatui and
5//! is still commonly used, especially for simple widgets that are created fresh each frame.
6//!
7//! This example runs with the Ratatui library code in the branch that you are currently
8//! reading. See the [`latest`] branch for the code which works with the most recent Ratatui
9//! release.
10//!
11//! [`latest`]: https://github.com/ratatui/ratatui/tree/latest
12//!
13//! ## When to Use This Pattern
14//!
15//! - You're working with existing code that uses this pattern
16//! - Your widgets are simple and created fresh each frame
17//! - You want maximum compatibility with older Ratatui code
18//! - You don't need to reuse widget instances
19//!
20//! ## Trade-offs
21//!
22//! **Pros:**
23//! - Simple - straightforward implementation
24//! - Compatible - works with all Ratatui versions
25//! - Familiar - widely used pattern in existing code
26//! - No borrowing - no need to manage references
27//!
28//! **Cons:**
29//! - Consuming - widget is destroyed after each render
30//! - Inefficient - requires reconstruction for repeated use
31//! - Limited reuse - cannot store and reuse widget instances
32//!
33//! ## Example Usage
34//!
35//! The widget implements `Widget` directly on the owned type, meaning it's consumed
36//! when rendered and must be recreated for subsequent renders.
37
38use ratatui::buffer::Buffer;
39use ratatui::layout::Rect;
40use ratatui::widgets::Widget;
41use ratatui_state_examples::is_exit_key_pressed;
42
43/// Demonstrates the consuming widget pattern for immutable state rendering.
44///
45/// Creates a new counter widget instance each frame, showing how the consuming
46/// pattern works with immutable state that's managed externally.
47fn main() -> color_eyre::Result<()> {
48    color_eyre::install()?;
49    ratatui::run(|terminal| {
50        let mut count = 0;
51        loop {
52            terminal.draw(|frame| {
53                // Widget is created fresh each time and consumed when rendered
54                let counter = Counter::new(count);
55                frame.render_widget(counter, frame.area());
56            })?;
57            // State updates happen outside of widget lifecycle
58            count += 1;
59            if is_exit_key_pressed()? {
60                break Ok(());
61            }
62        }
63    })
64}
65
66/// A simple counter widget that displays a count value.
67///
68/// Implements `Widget` directly on the owned type, meaning the widget is consumed
69/// when rendered. The count state is managed externally and passed in during construction.
70struct Counter {
71    count: usize,
72}
73
74impl Counter {
75    /// Create a new counter widget with the given count.
76    fn new(count: usize) -> Self {
77        Self { count }
78    }
79}
80
81impl Widget for Counter {
82    fn render(self, area: Rect, buf: &mut Buffer) {
83        // Widget is consumed here - self is moved, not borrowed
84        format!("Counter: {}", self.count).render(area, buf);
85    }
86}
